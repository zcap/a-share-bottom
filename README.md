# 股票 · 距历史最低（A股 / 港股 / 美股）

这个项目每天自动计算 A 股（沪深 + 北交所）、港股（主板 + 创业板）、美股（普通股 + ADR）全部上市股票的：

> **比值 = 当前股价 ÷ 上市以来最低价**（等比复权，历史最低价包含发行价）

A 股另有价值、质量、成长、综合四个分数（港美股的评分在下一步加入）。

结果发布成一个网页，顶部可以切换市场，手机和电脑都能打开。数据在每个交易日收盘后自动更新；盘中点“获取实时价”可以看到最新比值。

整个项目运行在 GitHub 上，不需要服务器，也不收费。

## 一、部署步骤

大约需要 15 分钟。首次构建数据另需 1～3 小时，期间不用守着。

### 1. 注册 GitHub 账号

打开 https://github.com 注册，已有账号就直接登录。

### 2. 新建仓库

右上角 **+** → **New repository**：

- Repository name：随便起，例如 `a-share-bottom`（会出现在网址里）
- 选 **Public**（公开）。私有仓库发布网页需要付费
- 点 **Create repository**

### 3. 上传代码

在新仓库页面点 **uploading an existing file**，把解压后文件夹里的**全部内容**拖进去，然后点 **Commit changes**。

上传后检查仓库里有没有 `.github/workflows/update.yml`。以 `.` 开头的文件夹在 Mac 上默认隐藏，可能没传上去。如果没有，就手动建一个：

1. 点 **Add file** → **Create new file**
2. 文件名一栏输入 `.github/workflows/update.yml`（输入 `/` 时会自动变成文件夹）
3. 把压缩包里这个文件的内容粘贴进去，点 **Commit changes**

### 4. 打开网页发布功能

仓库 **Settings** → 左侧 **Pages** → **Build and deployment** 下的 **Source** 选 **GitHub Actions**。

### 5. 检查数据源能不能访问

1. 仓库顶部点 **Actions**。如果提示要启用 workflows，点绿色按钮启用
2. 左侧选 **A股：更新数据并发布网页** → 右侧 **Run workflow** → mode 选 **probe** → 点 **Run workflow**
3. 一两分钟后点进这次运行，在 **Summary** 页面查看检查结果：
   - BaoStock 相关全部 ✅：可以继续
   - BaoStock 有 ❌：沪深数据拿不到，网页无法更新。把 Summary 截图发给我
   - 其他项有 ❌：不影响沪深数据，只是北交所、实时价或发行价会降级

### 6. 首次构建

再点一次 **Run workflow**，mode 选 **rebuild**。它会下载 5000 多只股票的完整历史，大约 1～3 小时。

完成后访问：`https://<你的用户名>.github.io/<仓库名>/`

运行超过 5 小时会自动保存进度并结束，下一次运行会接着做，不用管。

### 7. 港股、美股首次运行

Actions 左侧分别选 **港股：更新数据并发布网页**、**美股：更新数据并发布网页** → **Run workflow**（mode 用默认的 daily）。港股约 10 分钟；美股第一次约 30～40 分钟（要回溯 2000 年以来的 IPO 发行价，没回溯完的下次运行接着做）。之后都是自动运行。

三个市场是三个独立的任务，各自保存状态（A 股 `data` 分支、港股 `data-hk`、美股 `data-us`），互不影响。每个任务完成后都会调用 **发布网页**，用三个市场最新的状态重新生成整个网页。

### 8. 之后全自动

| 北京时间 | 做什么 | 大约用时 |
|---|---|---|
| 周一至周五 17:10 | 港股每日更新（港股 16:10 收盘后） | 5～10 分钟 |
| 周一至周五 18:40 | A 股每日更新（BaoStock 当天数据入库后） | 2 分钟 |

| 周一至周五 22:40 | A 股补跑，以防 BaoStock 入库晚 | 2 分钟 |
| 周二至周六 06:40 | 美股每日更新（美股收盘后） | 10～15 分钟 |

## 二、常见问题

**运行失败（红色 ✕）怎么办？**
点进那次运行看 Summary 和日志。网页会保留上一次成功的数据，不会坏掉。偶发的网络失败等下一次定时运行即可；连续失败请把日志发给我。

**收到 GitHub 邮件说定时任务被停用？**
公开仓库 60 天没有活动时，GitHub 会暂停定时任务。到 Actions 页面点 **Enable workflow** 即可恢复。

**国内打开 github.io 很慢？**
可以免费把同一个仓库再部署到 Cloudflare Pages，作为备用地址。需要的话我可以补充步骤。

**想改更新时间？**
编辑 `.github/workflows/update.yml` 里的 `cron` 行。注意那里写的是 UTC 时间，等于北京时间减 8 小时。

## 三、实现方案

### 数据源（全部免费、无需注册）

**A 股**

| 用途 | 来源 | 说明 |
|---|---|---|
| 沪深股票列表、上市日期 | BaoStock `query_stock_basic` | 每次运行都刷新，自动加入新股、剔除退市股 |
| 沪深完整历史 | BaoStock `query_history_k_data_plus` + `query_adjust_factor` | 不复权日线（含前收盘价）+ 官方后复权因子 |
| 沪深每日增量 | BaoStock `query_daily_history_k_AStock` + `query_daily_adjust_factor` | 一次请求拿到全市场某一天的数据 |
| 北交所 | 北交所官网列表 + 腾讯日线 / 腾讯实时行情 | BaoStock 不覆盖北交所 |
| 发行价 | 东方财富新股数据（2010 年后上市 + 北交所）+ 东方财富 F10 发行资料（全部 A 股，含 1990 年代上市的） | 两者都没有时用上市首日前收盘价推断；换股吸收合并上市的没有发行价 |
| 网页实时价 | 腾讯行情 `qt.gtimg.cn` | 由你的浏览器直接请求 |
| 估值（价值分） | 沪深：BaoStock 全市场单日数据里的市盈率、市净率、市销率；北交所：腾讯行情 | 沪深不增加请求；北交所字段先和 BaoStock 核对一致才使用 |
| 财务与行业（质量分、成长分） | 东方财富数据中心“业绩报表”（`stock_yjbb_em`），一次取全市场某一报告期 | 约十几次请求，每周一次；用 收盘价 ÷ 每股净资产 和 BaoStock 市净率核对，对不上就不用 |

没有用东方财富的行情接口：它从 2026 年 10 月底开始，连续请求几次就会限流封 IP。

**港股、美股**

| 用途 | 来源 | 说明 |
|---|---|---|
| 股票列表（新股、退市） | 港交所官方证券列表；Nasdaq Trader 官方代码表 | 每次运行刷新。港股只保留主板、创业板的股本证券；美股去掉 ETF、优先股、权证、单位、封闭式基金，以及并购前的 SPAC 空壳 |
| 完整历史（含分红、拆合股） | Yahoo Finance（yfinance） | 每只股票 1 次请求取完整历史，每天从头重算 |
| 中文名、收盘价核对 | 腾讯行情 | 运行摘要里会列出和 Yahoo 收盘价一致的比例 |
| 发行价 | 港股：东方财富港股资料（招股价）；美股：纳斯达克 IPO 日历（约 2000 年以后） | 必须和数据第一天、上市首日收盘价对得上才采用 |
| 网页实时价 | 腾讯行情 | 可能有延迟 |

### 计算口径

- **复权**：等比后复权。上市首日因子为 1，每次分红、送转、配股后，因子乘以“前一日收盘价 ÷ 除权除息参考价”。
- **为什么用后复权**：
  - 上市首日因子为 1，发行价可以直接和后复权价比较；
  - 历史价格不会因为新的分红而改变，所以每天只需增量更新；
  - 不会像前复权那样出现负价。
- **比值**：当前后复权价 ÷ min(上市以来每日最低价的后复权值, 发行价)。等比复权下，这个比值和用前复权价算出的完全一样。
- **四个分数（0–100，越高越好）**：都在同行业内排名（东方财富行业分类；同行业不足 8 只时改为和全市场比较）。
  - 价值分：市盈率（TTM）、市净率、市销率（TTM）取倒数后排名取平均；亏损、资不抵债排最差。
  - 质量分：净资产收益率、销售毛利率、经营现金流 ÷ 净资产。
  - 成长分：营业收入同比、净利润同比。
  - 综合分 = 价值 × 50% + 质量 × 30% + 成长 × 20%，三项都有才给分。
  - 退市整理期股票（名称以“退”结尾）不参与评分，也不占同行业排名；比值照常计算。
  - 财报期：全市场统一用都已过披露截止日的最近一期，保证可比。
- **两种最低价口径**：可以用日内最低价，也可以用收盘价。网页上可以切换，也可以选择是否计入发行价。

### 港股、美股的计算

- Yahoo 的开高低收已按拆股、合股调整，Adj Close 再按分红等比调整，所以 `最低价 × (Adj Close ÷ Close)` 就是“今天口径”的等比复权最低价。比值和 A 股用后复权算出的口径一致。
- 发行价换算到今天口径：发行价 ÷ 上市后累计拆股倍数 × 上市首日的分红调整系数。
- 每天从完整历史重算：下载完整历史和只下载最近几天的请求次数一样多，从头重算能自动反映新的分红、拆合股和数据源的事后修正。某只股票当天下载失败，就沿用上次的结果。
- 只用已经收盘的日线：收盘前运行时，不计入今天这根盘中 K 线。
- 已知限制：Yahoo 的港股历史最早到 2000 年（更早上市的标 ※）；Yahoo 对港股供股一般不复权；单日涨跌超过 4 倍的标 ⚠（可能是拆合股没有复权）。

### A 股：每只股票只保存一行“状态”

不保存全部历史 K 线，每只股票只记录这些字段：

- 当前复权因子
- 最后收盘价
- 历史最低价（日内最低、收盘两种口径）及对应日期
- 发行价

每天来一根新 K 线，就更新一次：

1. 如果当天是除权除息日，更新复权因子。
2. 计算当天最低价、收盘价的后复权值，比旧的最低值低就替换。

全市场的状态是一个约 1 MB 的压缩表格，存在仓库的 `data` 分支，每次只保留一个提交，仓库不会变大。

### 容错设计

- **可重复运行**：同一天的数据重复处理会自动跳过，多跑几次结果不变。
- **漏跑补齐**：按交易日历逐日补；漏太多就自动全量重建。
- **数据异常保护**：某天有超过 15% 的股票“前收盘价对不上”，说明数据源有问题，放弃当天更新、保持原状。
- **缺数据不猜**：某只股票当天在全市场数据里缺失时，不猜测，改用它的完整历史单独重算。
- **停牌期间除权**：复牌日用除权前的因子核对参考价，不会重复复权。
- **每周核对**：后复权价一旦算出就不再变化，所以只要每只股票的“当前复权因子”和 BaoStock 一致，就说明没有漏算除权。每周只核对因子（每只一次小查询），对不上的才重算；每月再完整重建一次兜底。
- **只用完整入库的数据**：BaoStock 傍晚陆续入库，全市场单日数据不到 95% 时视为当天还没入库完，等下一次运行。
- **可续跑**：首次构建可分多次完成，进度自动保存。

### 网页里的实时价（A 股）

网页本身是静态的。数据文件 `data/latest.json` 里存了每只股票的收盘价、复权因子和历史最低价。点“获取实时价”时，浏览器直接向腾讯行情请求全市场最新价（约 90 次小请求），然后在页面里重新计算：

- 今天的最低价也计入历史最低；
- 今天如果是除权除息日，根据腾讯给出的昨收（参考价）自动调整因子。

  pages.yml        生成并发布网页（三个任务完成后都会调用）

## 四、在自己电脑上运行（可选）

```bash
pip install -r requirements.txt
python -m bottom probe     # 检查数据源
python -m bottom daily     # A 股（第一次会自动全量构建），结果在 site/ 目录
pip install -r requirements-global.txt
STATE_DIR=state-hk python -m bottom hk   # 港股
STATE_DIR=state-us python -m bottom us   # 美股
python -m bottom site      # 用三个市场的状态生成整个网页
python -m pytest tests     # 运行测试
```

数据仅供参考，不构成投资建议。
